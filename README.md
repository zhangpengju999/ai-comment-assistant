## 📖 中文说明

### 它解决什么问题

看到好内容想评论，但打字慢、不知道说什么、想维持统一人设？

这个助手把流程压缩到**三次点击**：

```
点悬浮球 → 📖 阅读当前屏幕 → 选平台版本 → 复制 → 粘贴发表
```

评论由你自己的 LLM API（DeepSeek / Qwen / Kimi / GLM 等 OpenAI 兼容接口）生成，
不内置任何模型，**不依赖任何第三方服务端**，API Key 只存在你手机本地。

### 功能

| 功能 | 说明 |
|---|---|
| 🎭 角色人设 | 在主界面设置"我是谁"，生成评论时代入你的人设 |
| 🎈 悬浮窗 | 56dp 悬浮球，置顶所有应用，可拖动，点击展开 |
| 📖 读屏 | 无障碍服务读取图文帖子的可见文字（自动去噪、截断） |
| 💬 三平台点评 | **抖音版**：口语短句 + 互动钩子（50~80字）；**小红书版**：亲测分享感 + emoji（~100字）；**视频号版**：稳重真诚少 emoji（80~100字） |
| 📋 一键复制 | 生成的评论直接进剪贴板 |
| 🔒 隐私 | 无账号体系，不采集数据，配置仅存 SharedPreferences |

### 快速开始

#### 构建

1. 用 **Android Studio**（Koala 或更新，AGP 8.5 + JDK 17）打开本仓库，自动同步依赖
2. 连接手机（开发者选项 → USB 调试），点 Run；或命令行：

```bash
./gradlew assembleDebug
```

#### 首次使用（手机上）

1. 打开 App，填写：**角色人设**、**API 地址**（默认 `https://api.deepseek.com`）、**API Key**、**模型名**，点「保存设置」
2. 点「授权悬浮窗权限」→ 允许"显示在其他应用上层"
3. 点「开启无障碍服务」→ 开启「AI评论小助手读屏服务」
4. 点「启动悬浮窗」，悬浮球出现即就绪

#### 日常使用

1. 打开抖音 / 小红书 / 视频号的任意图文帖子
2. 点悬浮球 →「📖 阅读当前屏幕」预览读到的内容
3. 点平台按钮生成评论 →「复制评论」→ 粘贴发表

### 技术架构

```
MainActivity        配置页：角色人设 + API 配置 + 权限引导
FloatingService     前台服务 + WindowManager 悬浮窗（拖动 / 展开 / 收起）
AssistReaderService 无障碍服务：遍历节点树读取屏幕可见文字
CommentGenerator    OkHttp 调用 OpenAI 兼容接口，按平台拼 prompt
Prefs               SharedPreferences 存储配置
```

- Kotlin，无第三方业务 SDK，仅 `okhttp` 一个网络库
- 读屏方案选了**无障碍节点树**而非截屏 OCR：实时、免费、对图文文字最准
- 评论生成走用户自配 API 而非本地模型：端侧小模型质量撑不起"像真人评论"

### 当前版本限制（v1.0）

- 只支持**图文**：读的是屏幕可见文字；帖子里图片的 OCR（计划接 ML Kit）和视频口播 ASR 暂不支持
- 部分 App 用自绘引擎（H5 容器 / 游戏），读不到节点属正常现象
- 需要自备一个 OpenAI 兼容 API Key

### ⚠️ 免责声明

- 本工具仅生成评论文本，**发表由用户手动完成**，请务必人工审核后再发
- 各平台（抖音/小红书/视频号）的用户协议普遍限制自动化工具，频繁批量使用 AI 评论可能触发风控甚至封号，**请仅作为个人辅助写作工具使用，勿用于批量营销**
- 开启无障碍服务前请知悉：本 App 只在你主动点击时读取屏幕文字，不后台采集、不上传任何数据（源码可自行审计）
- 使用本软件产生的任何后果由使用者自行承担

## 📖 English

### What problem does it solve

You see a good post and want to comment — but typing is slow, you don't know what to say, or you want to keep a consistent persona.

This assistant compresses the flow into **three taps**:

```
Tap the floating ball → 📖 Read screen → Pick a platform style → Copy → Paste & post
```

Comments are generated by **your own** LLM API (any OpenAI-compatible endpoint: DeepSeek, Qwen, Kimi, GLM, …).
No model is bundled, **no third-party backend is involved**, and your API key stays on your device.

### Features

| Feature | Description |
|---|---|
| 🎭 Persona | Set "who I am" in the main screen; the persona is injected into every generated comment |
| 🎈 Floating window | A 56dp floating ball on top of all apps, draggable, tap to expand |
| 📖 Screen reading | Reads visible text of image-and-text posts via an Accessibility Service (with de-noising and truncation) |
| 💬 Three platform styles | **Douyin**: short colloquial lines + interaction hook (50–80 chars); **Xiaohongshu**: first-hand sharing tone + emoji (~100 chars); **WeChat Channels**: calm and sincere, minimal emoji (80–100 chars) |
| 📋 One-tap copy | Generated comment goes straight to the clipboard |
| 🔒 Privacy | No accounts, no data collection, config stored only in SharedPreferences |

### Quick start

#### Build

1. Open this repo in **Android Studio** (Koala or newer, AGP 8.5 + JDK 17); dependencies sync automatically
2. Connect your phone (Developer options → USB debugging) and hit Run, or build from CLI:

```bash
./gradlew assembleDebug
```

#### First run (on the phone)

1. Open the app and fill in: **persona**, **API base URL** (default `https://api.deepseek.com`), **API key**, **model name**, then tap "Save"
2. Tap "Grant overlay permission" → allow "Display over other apps"
3. Tap "Open accessibility settings" → enable "AI Comment Assistant Reader"
4. Tap "Start floating window" — once the ball appears, you're ready

#### Daily usage

1. Open any image-and-text post on Douyin / Xiaohongshu / WeChat Channels
2. Tap the floating ball → "📖 Read screen" to preview the captured content
3. Tap a platform button to generate a comment → "Copy" → paste and publish

### Architecture

```
MainActivity        Config screen: persona + API settings + permission onboarding
FloatingService     Foreground service + WindowManager overlay (drag / expand / collapse)
AssistReaderService Accessibility Service: walks the node tree to read on-screen text
CommentGenerator    OkHttp call to an OpenAI-compatible endpoint, prompts per platform
Prefs               SharedPreferences-based config storage
```

- Kotlin, no third-party business SDK — only `okhttp` for networking
- Screen reading uses the **Accessibility node tree** instead of screenshot OCR: real-time, free, and most accurate for text-heavy feeds
- Comment generation goes through the user's own API rather than an on-device model: small on-device models cannot deliver a "human-like comment"

### Limitations (v1.0)

- **Image-and-text only**: it reads visible on-screen text; OCR for images (ML Kit planned) and ASR for video speech are not supported yet
- Some apps render with custom engines (H5 containers / games); no node tree is available there — expected behaviour
- You need your own OpenAI-compatible API key

### ⚠️ Disclaimer

- This tool only **generates** comment text; **posting is done manually by the user** — always review before you publish
- Major platforms (Douyin / Xiaohongshu / WeChat Channels) restrict automation in their terms of service; frequent bulk AI commenting may trigger risk control or even account bans. **Use it only as a personal writing aid, never for bulk marketing**
- Before enabling the Accessibility Service, note that this app reads on-screen text **only when you actively tap a button** — nothing is collected in the background and nothing is uploaded (the source is yours to audit)
- Any consequence of using this software is borne by the user
